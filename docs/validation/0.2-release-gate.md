## 关键兼容性证据

真实升级 fixture 使用 `git archive 22e0475` 生成旧版本 source，并由旧版本完成 registration、Capture、Curate proposal 与 approval。随后当前固定 HEAD 对同一 Vault 执行 0.2 检索与视图能力。

升级前后独立比较确认：

- stable identity 不重新生成；
- revision history 不重置；
- proposals 不丢失；
- 用户 Markdown 不批量重写；
- 0.1 Exact / Filter / Full-text 继续可用；
- 0.2 relation schema 与 Bases Projection 以增量方式加入。

## 关键失败路径证据

独立验收确认：

- structured Authority store 缺失时 fail closed，且不自动创建空数据库；
- SQLite 损坏时 fail closed，且 Markdown 保持不变；
- duplicate stable identity 时 fail closed；
- FTS Projection 污染后可从当前 Authority 恢复正确检索结果，revision 不推进；
- Bases Projection 删除或损坏后可重建，Authority 与 revision 不变；
- 未支持的 future scope 不虚构生命周期状态；
- 未拥有的同名 view 目录拒绝覆盖，用户文件保持不变；
- 普通 wikilink 不被解释为 typed relation；
- `0.2.x` 不暴露 relation create / accept / edit 用户入口。

## 最终门禁

`0.2.x` 在固定实现 HEAD 上满足：

- Source Spec #25 的 Retrieval + Views 目标状态；
- #30 的完整用户闭环；
- #31 的升级兼容、fail-closed、Projection recovery 与 0.1 回归门禁；
- 独立 Agent 黑盒验收 `accepted`；
- 没有确认的 Blocking defect。

因此 `0.2.x` 可以标记为**实现完成并通过发布就绪门禁**。

该结论不等于已经创建 GitHub tag / release，也不等于已经执行远端安装发布；在正式发布流程完成前，仍不得把 `0.2.x` 描述为已发布稳定版本。
