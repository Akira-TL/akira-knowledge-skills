## Revision-safe maintenance 证据

0.4 各治理层保持现有 Authority contract：

- Source Review / semantic conflict / Relation maintenance 只形成 governance record，不直接 mutation；
- retire / supersede 必须 explicit approval，并重新验证 revision / lifecycle basis；
- human wikilink / user Property 修改先形成 revision-bound Authority edit proposal，批准前 Markdown 不变；
- Batch 只引用既有 governed proposal / candidate，不接受任意正文、target 或 relation triple；
- Batch 每项保存自己的 identity / relation identity、revision / fingerprint basis、evidence、proposed change、approval result 与 execution result；
- stale / failed item 不覆盖较新 Authority，且不会把整批伪装为成功；
- 已成功 item 重复执行不再次 mutation，不制造无意义 revision；
- relation mutation 始终复用 Relation Candidate / approval / expected-revision revoke，没有第二套 Relation Authority 写入口。

## Projection / diagnostic 边界

最终黑盒确认：

- network health 是只读诊断；
- Source Review / conflict / Batch 输出不是 Knowledge Object；
- Bases / Relation Graph 是 rebuildable Projection；
- health / Views / Graph rebuild 不推进无关 Knowledge / Relation revision；
- retired / superseded 的默认 Retrieval Scope 与显式 lifecycle scope 均消费 structured lifecycle Authority，而不是从 Projection 反推状态。

## Fail-closed 证据

0.4 canonical 黑盒与专项覆盖以下失败路径：

- Source 不可稳定核验 → unknown，不伪报 changed / stale；
- Source identity 不一致 → fail closed；
- Source / conflict / Relation maintenance candidate basis 变化 → stale；
- retire / supersede proposal basis 变化 → fail closed；
- duplicate stable identity → fail closed；
- ambiguous local Knowledge wikilink target → fail closed；
- structured Authority store 缺失 / 对应当前 schema governance table 缺失 → fail closed；
- Batch item basis / underlying governance 已变化 → stale 或 failed，其他独立 item 可继续；
- 用户未 explicit approval 的 Authority mutation 不执行；
- ordinary wikilink / tag / 全文共现 / 模型相似度不自动升级为 Relation Record。

## 明确未引入的能力

0.4 没有引入以下能力域：

- vector DB / embedding；
- hybrid retrieval / rerank / graph ranking；
- 大型 relation ontology；
- inverse / symmetry / transitive 自动推理；
- 模型置信度驱动的自动 Authority approval；
- runtime Context / Memory；
- Knowledge 自有后台 daemon / scheduler；
- Multi-Agent maintenance claim / lock / merge protocol。

这些边界继续由后续路线图与证据门控制。

## 最终门禁

固定实现 981138e 满足 #39 / #46 的 0.4 Long-term Maintenance 目标状态，并在门禁测试提交 bc5c31f 上取得：

- 0.4 最终 public-surface black-box：PASS；
- 真实 0.3 → 0.4 in-place upgrade：PASS；
- canonical regression：127/127 PASS；
- structured Authority integrity / foreign key consistency：PASS；
- 没有确认的 Blocking defect。

因此 0.4.x 可以标记为实现完成并通过发布就绪门禁。

该结论不改变仓库的发布状态：在 GitHub tag / release 与正式发布流程完成前，仍不得把 0.4.x 描述为已经发布的稳定版本。
